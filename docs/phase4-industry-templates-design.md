# Phase 4 設計書: 業種別メッセージテンプレート自動選択（ドラフト v0.1）

> **Codex 向け実装指示書（ドラフト）**
> 文面生成を「業種ごとに最適な提案の型」で自動的に切り替える仕組み。
> 既存の `message_templates` / `prompt-builder.ts` を拡張する。新規の生成エンジンは作らない。

---

## 概要

### 目的
リードの `industry`（業種）に応じて、メッセージ構成テンプレート（`message_templates.structure`）を
**自動選択**し、業種ごとに最適化された提案文を生成する。

### なぜ業種別か（商材との対応）
CONOCOLA の商材は業種によって「刺さる提案の型」が根本的に異なる:

| 提案の型 | 対象業種 | 主な商材・訴求 |
| --- | --- | --- |
| A. ドリンク導入型（提供・食中） | サウナ / カフェ / 中華 / 焼肉 / フレンチ / イタリアン / キッチンカー | サウナーコーラをメニューへ（設備投資ゼロ・教育不要・単価UP・SNS映え） |
| B. 物販・小売・卸型 | 美容サロン / 雑貨屋 / スーパーマーケット / 高級食品スーパー / お土産屋 / 百貨店 | 瓶コーラの物販・仕入れ・棚・催事・ギフト（美容サロンは**施術後の物販**） |
| C. OEM型（第2提案） | 全業種（特に百貨店・お土産屋・大型施設・サロン） | 施設/店オリジナルクラフトコーラ（小ロット対応・IP/ホテル実績） |

---

## 現状の機構（変更しない部分）

- `leads.industry`（text）は存在し、`buildUserPrompt` が「業種: X」としてプロンプトに渡している
- `message_templates`（name / description / structure / is_default / sort_order）は存在し、
  `structure` が `buildSystemPrompt` の【メッセージ構成テンプレート】に注入される
- `instagram_targets.industry` も存在（DM生成 `/api/generate-dm` で使用）
- 商材・強み・実績は `user_settings`（products / value_propositions / social_proof）から注入される
  → **業種テンプレは「どの訴求角度を使うか」を指示する役割**。商材データ自体は user_settings のまま

## 変更点

### 1. DB: migration `018_add_industry_to_message_templates.sql`

```sql
alter table public.message_templates
  add column if not exists industry text;

create index if not exists message_templates_industry_idx
  on public.message_templates(user_id, industry);
```

- `industry` は NULL 可。NULL = 汎用テンプレ（従来どおり）
- 値は業種マスタ（下記）の正規名のみを想定（UIでセレクト入力にして揺れを防ぐ）

### 3. テンプレ自動選択ロジック

`/api/generate` と `/api/generate-bulk`（および将来 `/api/generate-dm`）のテンプレ解決を共通化:

```ts
// src/lib/template-resolver.ts（新規・薄い関数1つ）
export async function resolveTemplate(
  supabase, userId: string,
  explicitTemplateId: string | null,   // UIで手動選択された場合
  leadIndustry: string | null,
): Promise<MessageTemplate | null>
```

優先順位:
1. **UIで明示選択されたテンプレ**（従来動作を壊さない・手動上書き可能）
2. `normalizeIndustry(lead.industry)` に一致する `industry` のテンプレ
3. `is_default = true` のテンプレ
4. null（テンプレなし生成）

### 4. UI 変更（最小）

- テンプレ編集モーダル: 業種セレクト（13業種 + 「汎用」）を1つ追加
- 文面生成画面: テンプレ選択の初期値を「自動（業種で選択）」にする
  - 生成後のUIに「使用テンプレ: 焼肉向け」のように表示すると検証しやすい（任意）

### 5. カフェパイプラインとの接続

- `cafe_prospects` → `leads` 昇格時（Phase 4/昇格フロー実装時）に `industry = 'カフェ'` を自動セット
- Phase 3-IG の橋渡しでは `instagram_targets.industry = 'カフェ'` を既に設定する設計（整合済み）

## 13業種の初期テンプレ（structure 初期データ）

> seed スクリプト or 設定画面から一括投入。**文面は初期案** — 反応率を見て改訂する前提。
> structure は `buildSystemPrompt` の【メッセージ構成テンプレート】に注入される「構成・訴求角度の指示」。

### サウナ（本命・実績最強）
```
【業種: サウナ】提案の型 = ドリンク導入 + サ飯
- 書き出し: 施設のサウナ設備・水風呂・ロウリュ等のこだわりをHPから具体的に引用
- 主提案: サウナ専用コーラ「サウナーコーラ」。サウナ後の一杯としての体験価値
- 数字: 全国60施設以上・大型施設で週1,000杯・小型店でも1日7杯を必ず入れる
- 導入障壁の低さ: 設備投資ゼロ・教育不要・即日導入を明記
- 第2提案: サ飯（冷凍スパイスカレー）— キッチンが狭くてもサウナ飯を出せる
- 同業導入例: King&Queen・キャナルリゾート等から施設規模が近いものを1つ
```

### カフェ
```
【業種: カフェ】提案の型 = ドリンクメニュー差別化
- 書き出し: 店の世界観・豆や焙煎・空間のこだわりをHP/Instagramから引用
- 主提案: クラフトコーラはコーヒー以外の選択肢（ノンカフェイン需要・お連れ様需要）
- 訴求: 無添加・無着色でカフェの健康志向客層と相性が良い。SNS映えで新規集客
- 数字: 単価向上とリピート実績を1つ
- 第2提案: 店名入りオリジナルコーラのOEM（小ロット可）→ 物販・ギフトにも
- 注意: コーヒーへのこだわりを否定しない。「コーヒーの妨げにならない一杯」の文脈
```

### 中華
```
【業種: 中華】提案の型 = 食中ドリンク
- 書き出し: 看板メニュー（餃子・麻婆・点心等）をHPから引用
- 主提案: スパイス10種の クラフトコーラ × 中華の相性（餃子×コーラは食中の定番）
- 訴求: ノンアル需要の受け皿・ドリンク単価UP・ファミリー層の満足度
- 数字: 導入施設数とリピート率
- 第2提案: 店オリジナルコーラOEM
```

### 焼肉
```
【業種: 焼肉】提案の型 = 食中ドリンク（相性最強帯）
- 書き出し: 肉のこだわり・産地・名物メニューをHPから引用
- 主提案: 焼肉×コーラは鉄板の組み合わせ。クラフトコーラで「どこにでもあるコーラ」から差別化
- 訴求: 車来店・家族客のノンアル需要、ドリンク単価UP、無添加で子供にも安心
- 数字: 導入実績・継続率
- 第2提案: 店名入りオリジナルコーラOEM（記念日・手土産需要）
```

### フレンチ
```
【業種: フレンチ】提案の型 = ノンアルペアリング
- 書き出し: シェフの経歴・コースのコンセプトをHPから引用（格式に合わせ丁寧トーン推奨）
- 主提案: 大人のノンアルコール選択肢としてのクラフトコーラ（生薬・スパイスの複雑味）
- 訴求: 妊娠中・運転のゲストへのペアリング提案、記念日利用の満足度
- ブランド: 2024年パリコレ提供・2026年高級外資ホテル導入予定を必ず入れる
- 第2提案: レストランオリジナルレシピのOEM（コースの世界観に合わせて開発）
```

### イタリアン
```
【業種: イタリアン】提案の型 = 食中ドリンク（カジュアル寄り）
- 書き出し: ピザ窯・パスタ・産地等のこだわりをHPから引用
- 主提案: クラフトコーラ × イタリアンのスパイス感。ランチセットのドリンク単価UP
- 訴求: ファミリー・ノンアル需要、SNS映え
- 数字: 導入実績
- 第2提案: 店オリジナルコーラOEM
```

### キッチンカー
```
【業種: キッチンカー】提案の型 = 省スペース・高利益ドリンク
- 書き出し: 出店スタイル・看板メニューをSNS/HPから引用
- 主提案: 瓶提供で映える・オペレーション極小（注ぐだけ）・在庫管理が楽
- 訴求: 設備投資ゼロはキッチンカーにこそ刺さる。イベントでの話題性・行列演出
- 数字: アウトドアサウナで1日20杯（屋外販売の実績として転用）
- 第2提案: 車体ブランドのオリジナルコーラOEM
```

### 美容サロン（＝美容関連。狙いは施術後の物販）
```
【業種: 美容サロン】提案の型 = 施術後の物販（テイクアウト購入）
- 書き出し: サロンのコンセプト・こだわり（髪質改善・オーガニック志向・美意識の高い客層等）を引用
- 主提案: 施術後にお客様が購入して持ち帰る「物販商品」としてのクラフトコーラ。
  無添加・無着色・生薬10種の“回復/ととのう/ご褒美”ドリンクとして、美容意識の高い客層に刺さる
- 販売モデル: レジ横・待合・会計動線での陳列販売。低単価・高粗利・在庫リスク小（瓶・常温保存）
- 訴求: 施術で高まった「自分をいたわる」気分のまま買える体験導線。リピート物販で客単価・LTV向上
- ブランド: 無添加・メディア掲載（NHK等）・パリコレ提供実績で“サロンが置く理由”を補強
- 第2提案: サロンオリジナルラベルのOEM（自店ブランドの物販商品を小ロットで持てる）
- 注意: 「サウナ用」を前面に出さない。“美容・回復・ご褒美・セルフケア”の文脈に翻訳する
- 推奨トーン: フレンドリー〜丁寧（サロンの格に合わせる）
```

### 雑貨屋
```
【業種: 雑貨屋】提案の型 = 仕入れ・物販
- 書き出し: 店のセレクト基準・世界観をHP/Instagramから引用
- 主提案: 瓶ボトルのデザイン性 × 名古屋発ストーリーで「置くだけで語れる商品」
- 訴求: ギフト需要・小ロット仕入れ可・メディア掲載多数で説明いらず
- 数字: 60施設導入・メディア実績（NHK等）
- 第2提案: 店オリジナルラベルのOEM（自店ブランド商品が小ロットで持てる）
```

### スーパーマーケット
```
【業種: スーパーマーケット】提案の型 = 卸売・地元商品棚
- 書き出し: 地域密着・地元商品の取り扱い方針等をHPから引用
- 主提案: 「名古屋発・メディア多数掲載」の地元クラフトコーラとして地場商品コーナーへ
- 訴求: メディア露出（NHK・東海テレビ等）による指名買い・話題性での回転
- 数字: 60施設導入・継続率
- 取引条件: 小ロットから・柔軟対応を明記
```

### 高級食品スーパー
```
【業種: 高級食品スーパー】提案の型 = プレミアム棚・ギフト
- 書き出し: 品揃えのこだわり・バイヤーの目利き方針を引用（丁寧トーン推奨）
- 主提案: 無添加・無着色・生薬10種のプレミアムクラフトコーラ
- ブランド: パリコレ提供・高級外資ホテル導入予定・アニメIP/球場コラボ実績を前面に
- 訴求: ギフト需要・健康志向の客層との親和性・価格帯の整合
- 第2提案: 店舗限定ラベルのOEM
```

### 百貨店
```
【業種: 百貨店】提案の型 = 催事・ポップアップ・ギフト
- 書き出し: 催事企画・地元名品コーナー等の取り組みを引用（最も丁寧なトーン）
- 主提案: 催事出店 or 常設棚。名古屋発ブランドストーリー＋メディア実績で集客貢献
- ブランド: パリコレ・外資ホテル・IPコラボの実績を必ず入れる（バイヤー向け信頼材料）
- 訴求: ギフト・お中元お歳暮文脈、話題性による催事集客
- 第2提案: 百貨店限定パッケージのOEM
```

### お土産屋
```
【業種: お土産屋】提案の型 = ご当地商品・OEM
- 書き出し: 立地（観光地・駅・SA等）と売れ筋の文脈を引用
- 主提案: 「名古屋発クラフトコーラ」としてのご当地性 + 瓶の持ち帰りやすさ/ギフト性
- 第2提案（ここではほぼ主提案）: ご当地オリジナルコーラのOEM — その土地の名前・素材で
  小ロットから作れる。観光地限定商品の実績文脈（IP・時代劇コラボ）
- 訴求: 他店に無い限定商品が低リスクで持てる
```

## データフロー（生成時）

```
リード選択（industry あり）
   ↓
normalizeIndustry(lead.industry) → '焼肉'
   ↓
resolveTemplate: ①手動選択 > ②industry一致 > ③is_default > ④なし
   ↓
buildSystemPrompt(settings, template, tone)   ← 既存のまま
   ↓
業種特化の構成・訴求角度で文面生成
```

## 段階的導入

1. migration 018 + `industries.ts` + `resolveTemplate` 実装
2. seed: 13業種テンプレを message_templates に投入（上記初期データ）
3. まず**サウナ・カフェ・焼肉**の3業種で生成品質を目視確認（既存リードで --dry-run 的に生成のみ）
4. 反応率が測れるようになったら business ごとに structure を改訂

## 実装順序（Codex 向け）

1. `supabase/migrations/018_add_industry_to_message_templates.sql`
2. `src/lib/industries.ts`（マスタ + normalizeIndustry + 単体で dry-run 確認）
3. `src/lib/template-resolver.ts`
4. `/api/generate` と `/api/generate-bulk` に resolveTemplate を組み込み（手動選択を壊さない）
5. テンプレ編集UIに業種セレクト追加
6. seed スクリプト（`scripts/seed-industry-templates.ts`）で13テンプレ投入
7. 既存リード（サウナ）1〜2件で生成確認 → 出力に業種訴求が反映されているか目視
